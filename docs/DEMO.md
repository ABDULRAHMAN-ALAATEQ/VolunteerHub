# 10-minute demonstration (plus 5 minutes for questions)

| Time|Show |
| 0:00–1:00 | Client problem, roles, individual charter and project scope. |
| 1:00–2:00 | SMART backlog, two sprint goals, genuine Git history and remaining approval status. |
| 2:00–3:30 | Organization signs in, publishes upcoming opportunity, edits its details and sees participants. |
| 3:30–5:30 | Student signs in, AJAX search, registration, dashboard, completed Community food drive hour submission. |
| 5:30–7:30 | Deanship reviews the submitted log; approve it and issue the certificate. If time allows, show rejection/resubmission using the seeded pending record or perform it beforehand in rehearsal. |
| 7:30–8:30 | Student opens the certificate and print/PDF preview. |
| 8:30–9:30 | Show actual requirement-change record if received, test results and security boundaries. |
| 9:30–10:00 | Retrospective and request client acceptance. |

Questions: 
Why Rails MVC?
How do you prevent overbooking and duplicate registration? 
Why separate approvals from certificate issuance? 
What happens when an unauthorised user attempts to access another record? 
How is a change managed? 
Why SQLite for a classroom prototype rather than a production database?
